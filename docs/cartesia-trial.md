# ทดลอง Cartesia Free

## อัปเดต 2026-09-21: ผู้ใช้ทดสอบผ่านเบราว์เซอร์จริงแล้ว — ผ่าน ใช้ได้

ทดลองคุยด้วยเสียงจริง (mic → Typhoon → เสียงโคลน Cartesia ในเบราว์เซอร์) ผลสรุป: **ใช้ได้เลย**
ในโหมดเสียง คุณภาพเสียงไทยของเสียงโคลนผ่านตามเกณฑ์ผู้ใช้ (ต่างจากเสียงสำเร็จรูป Suda รอบแรก
ที่ตกไปก่อนหน้านี้) ถือว่าปิดข้อกังวลเรื่องคุณภาพภาษาไทยที่ค้างไว้ในหัวข้อ "งานถัดไป" ด้านล่างแล้ว

ยังไม่ได้ทดสอบ: พูดแทรกกลางประโยคเสียงโคลน, เครดิต Cartesia หมด, เน็ตหลุดกลางสตรีม — ไม่ใช่
เงื่อนไขบล็อกการใช้งานปกติ แต่ควรลองก่อน deploy ขึ้น production จริง

## อัปเดต: รวม UI เลือกเสียง — ตัด dropdown ระบบเสียง + ช่อง URL Colab ออก

ผู้ใช้ตัดสินใจใช้ Cartesia เป็นระบบหลักแล้ว จึงเอา UI ที่แยก "ระบบเสียงตอบกลับ" (Cartesia/
Browser/Colab) กับช่อง "URL เซิร์ฟเวอร์เสียงโคลน (Colab/Kaggle)" ออกทั้งคู่ เหลือแค่ช่อง
**"เสียงพูด"** เดียว (`#opt-voice`) ที่รวมทั้งเสียงโคลน Cartesia (optgroup "เสียงโคลน (Cartesia)")
กับเสียงของเบราว์เซอร์ไว้ในลิสต์เดียวกัน — เลือก "ASN" = เสียงโคลน Cartesia (จาก voice ID ที่
ผู้ใช้สร้างด้วย Instant Clone), เลือกเสียงอื่นในลิสต์ = เสียงเบราว์เซอร์เหมือนเดิม

เตรียมรองรับเพิ่มเสียงโคลนอื่นในอนาคต (เช่น ถ้าจะโคลน Kirito ด้วย): เติมรายการใน
`CARTESIA_VOICES` ที่ต้นไฟล์ `static/js/voice.js` (`{id, name}`) — ฝั่ง client ส่ง `voice_id`
ที่เลือกไปกับทุก request ของ `POST /api/v1/tts/stream`, `channels/tts.py` ใช้ค่านั้นแทน
`CARTESIA_VOICE_ID` ของ `.env` ถ้ามีส่งมา (ไม่ส่ง = ใช้ค่า default ของเซิร์ฟเวอร์เหมือนเดิม)

path ของ Colab/Kaggle (`voice_server.ipynb`) ยังอยู่ในโค้ด/repo `Voice chatbot` เหมือนเดิม
แค่ไม่มีทางเรียกจาก UI ของแอปนี้แล้ว — ถ้าจะกลับไปใช้ต้องต่อ UI ใหม่

## อัปเดต 2026-09-14: ได้เสียง Instant Clone แล้ว

ผู้ใช้สร้างเสียงโคลนสำเร็จแล้ว ตั้ง `CARTESIA_VOICE_ID` ใน `.env` เป็น ID ของเสียงโคลน
และใช้ `CARTESIA_API_KEY` ของบัญชีที่เข้าถึงเสียงนั้นได้ จากนั้นรีสตาร์ทเซิร์ฟเวอร์
เลือก Settings > เสียงพูด > ASN (เสียงโคลน Cartesia ในกลุ่ม "เสียงโคลน (Cartesia)") แล้วเปิดโหมดเสียงใหม่
หากนำขึ้น Vercel ให้ตั้งค่าทั้งสองตัวใน environment ของ Vercel และ deploy ใหม่ด้วย

ระบบเดิมส่ง voice ID จาก environment ไปยัง Cartesia อยู่แล้ว จึงใช้เสียงโคลนกับ
คำตอบ Typhoon ได้โดยไม่ต้องติดตั้ง Cartesia SDK หรือ ffplay เพิ่ม
คง PCM streaming 24 kHz เพื่อให้ตรงกับตัวเล่นในเว็บ; ตัวอย่าง WAV 44.1 kHz
เหมาะกับการบันทึกไฟล์และไม่จำเป็นต้องนำมาแทนระบบสตรีมเดิม

ตั้งค่าเสียงโคลนในเครื่องแล้ว แต่ยังไม่ได้ทดสอบฟังผ่านแอปหรือยืนยันคุณภาพภาษาไทย
ควรลองภาษาไทย ภาษาอังกฤษ ประโยคผสม และการหยุดเสียงระหว่างตอบ
บันทึกด้านล่างเป็นผลทดลองเสียง Suda ก่อนเปลี่ยนเป็นเสียงโคลน

**ยืนยันแล้วว่า wiring ทำงานถูกต้อง:** ยิง `POST /api/v1/tts/stream` ตรง (ข้ามเบราว์เซอร์)
ด้วยข้อความสไตล์คำตอบ chatbot ("สวัสดีค่ะ วันนี้อากาศดีมาก มีอะไรให้ช่วยไหมคะ") ผ่าน
`uvicorn` ในเครื่อง ได้ PCM กลับมาจริง (24 kHz mono, ~4.16 วิ) ด้วยเสียงโคลนตาม
`CARTESIA_VOICE_ID` ใน `.env` — สรุปว่า backend → Cartesia → เสียงโคลน ทำงานได้เต็ม pipeline
**ยังไม่ได้ฟังผ่านเบราว์เซอร์จริง** (mic เปิด → LLM ตอบ → เสียงเล่นในหน้าเว็บ) — ผู้ใช้ตัดสินใจ
ใช้ Cartesia เป็นระบบหลักแล้วจากคลิปนี้ ก่อนไปขึ้น Vercel ควรลองในเบราว์เซอร์เครื่องนี้อย่างน้อย 1 รอบ

## อัปเดต: แก้เสียง "ตึ๊ด" คั่นระหว่างประโยค (`static/js/voice.js`)

ทดสอบบน Vercel Preview จริงแล้วพบเสียงคลิกสั้นๆ คั่นตอนบอทกำลังพูด — สาเหตุคือแต่ละประโยคเป็น
**คนละ synthesis call** (คนละ request ไป Cartesia/Colab) คลื่นเสียงที่ขอบไม่ได้ต่อเนื่องกันจริง
พอตัดสลับกันตรงๆ แบบไม่มีช่องว่างเวลา (ตามที่ตั้งใจไว้ให้ gapless) เลยได้ยินเป็น click/discontinuity

แก้ด้วยการเติม fade in/out สั้น 10ms ที่ `scheduleBuffer()` ผ่าน `GainNode` — **เฉพาะตรงรอยต่อ
ระหว่างประโยค** เท่านั้น: ท่อนของ Colab (ไฟล์เต็มประโยคต่อ 1 request) fade ทั้งสองขอบเสมอ
ส่วนของ Cartesia (สตรีม PCM ผ่าเป็น sub-chunk ~100ms ภายใน 1 request เดียว) ใช้วิธี "กัน" sub-chunk
ล่าสุดไว้หนึ่งก้อนก่อน schedule เสมอ (schedule ก้อนก่อนหน้าแทน) เพื่อให้รู้แน่ชัดว่าก้อนไหนเป็นก้อนแรก/
สุดท้ายของประโยคนั้น — sub-chunk ภายในหนึ่ง stream เป็นคลื่นเสียงต่อเนื่องอยู่แล้วจริงๆ **ไม่ fade**
ระหว่างกัน (ใส่จะกลายเป็นเสียงสั่นเป็นจังหวะทุก 100ms แทนที่จะลบคลิก)

## สถานะ 2026-09-13

เชื่อม Cartesia และ Typhoon สำเร็จ และผู้ใช้ทดลองฟังผ่านเว็บแล้ว:
ความเร็วพอใช้งานได้ แต่การอ่านภาษาไทยของเสียง Suda ยังไม่ดีพอตามความเห็นผู้ใช้
ยังไม่ได้สร้างหรือทดลองเสียงโคลนบน Cartesia และยังไม่ได้สมัครแพ็กเกจเสียเงิน
พักการทดลองไว้เพื่อพิจารณาขั้นต่อไป ไม่ถือว่าคุณภาพเสียงไทยผ่านการยอมรับแล้ว

ตาม [หน้าราคา Cartesia](https://www.cartesia.ai/pricing) ที่ตรวจในวันที่ข้างต้น
Free มี 20,000 เครดิต/เดือน (ประมาณ 27 นาทีเสียง) และ Instant Voice Cloning เริ่มใน Pro
ราคา $5/เดือน ข้อมูลแพ็กเกจอาจเปลี่ยนได้ ให้ตรวจอีกครั้งก่อนสมัคร

ผลทดสอบจริงด้วยข้อความสั้น “สวัสดีค่ะ”:
- เรียก Cartesia โดยตรง: รับข้อมูลเสียงแรกประมาณ 0.30 วินาที รับครบประมาณ 0.47 วินาที
- เรียกผ่านแอป localhost: รับข้อมูลเสียงแรกประมาณ 0.96 วินาที
- เป็นการวัดคนละครั้ง ไม่ใช่ค่าเฉลี่ยหรือ benchmark; ตัวเลขผ่านแอปรวมการตรวจหน้าเว็บก่อนเรียกเสียง
- ไม่รวมเวลารู้จำเสียง เวลา Typhoon คิด/ค้นเว็บ และเวลาเริ่มเล่นจริงในเบราว์เซอร์

## ตั้งค่าและใช้งาน

ตั้ง `CARTESIA_API_KEY` ใน `.env` แล้วรัน `python -m uvicorn main:app --reload`.
เปิด http://127.0.0.1:8000 เลือก Settings > เสียงพูด > ASN แล้วเปิดไมโครโฟน
ช่อง "เสียงพูด" ตัวเดียวรวมทั้งเสียงโคลน Cartesia (กลุ่ม "เสียงโคลน (Cartesia)") และเสียง
ของเบราว์เซอร์ไว้ด้วยกัน — ไม่มีตัวเลือก provider แยกแล้ว (ตัด UI เดิมที่มีทั้ง dropdown
ระบบเสียงตอบกลับ และช่อง URL เซิร์ฟเวอร์ Colab ออก เพื่อลดความซับซ้อน)
เมื่อแก้ตัวเลือกขณะคุย โหมดเสียงจะปิด ให้เปิดใหม่เพื่อใช้ตัวเลือกใหม่

คีย์เก็บฝั่ง Python เท่านั้น เบราว์เซอร์เรียก `/api/v1/tts/stream` เพื่อรับ PCM
24 kHz mono signed 16-bit little-endian และเล่นระหว่างรับข้อมูล ไม่รอ WAV ทั้งไฟล์
เสียงแต่ละวลีถูกส่งตามลำดับ โดยเล่นเสียงที่เตรียมไว้ต่อเนื่องผ่าน AudioContext
การสร้างเสียงใช้เครดิตบัญชี Cartesia; แอปไม่ได้ตรวจยอดหรือป้องกันค่าใช้จ่ายส่วนเกินของบัญชี
ใช้บัญชี Free สำหรับการทดลองนี้ ไม่ต้องเปิด Colab เมื่อเลือก Cartesia

ตรวจสอบด้วย `python -m unittest discover -s tests` และ `node --check static/js/voice.js`.
การทดสอบ mock ไม่เรียกบริการจริงและไม่ใช้เครดิต
