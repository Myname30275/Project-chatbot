Test System — โครงระบบแชตบอต

แชตบอตภาษาไทยที่รันบน FastAPI + Vercel serverless คุยกับโมเดล Typhoon ผ่าน Chat Completions API แบบ OpenAI-compatible อ่านไฟล์แนบ จำได้หลายบทสนทนา ค้นเว็บมาตอบเองเมื่อถูกถามข้อมูลล่าสุด และมีโหมดสนทนาด้วยเสียง

FastAPI Uvicorn Jinja2 + vanilla JS SSE streaming Voice mode (บนเบราว์เซอร์) Typhoon LLM + OCR Gemini vision Tavily search Upstash Redis Vercel

01ภาพรวม

หลักการออกแบบที่ยึดตลอดทั้งโปรเจกต์

โค้ดฝั่งเซิร์ฟเวอร์ทั้งหมดอยู่ที่ main.py + routers/ + services/ เหมือนกันหมดไม่ว่าจะรันในเครื่อง (uvicorn main:app) หรือบน Vercel — ไฟล์ api/index.py เป็นแค่ตัวห่อ import app เข้ามา

  • ผู้ให้บริการ LLM ถูกแยกออกด้วยชื่อกลางๆ (LLM_BASE_URL, LLM_API_KEY, LLM_MODEL) — สลับจาก Typhoon ไป LM Studio หรือ OpenRouter ได้โดยแก้แค่ .env
  • ไม่มี RAG / vector store — ทั้งเนื้อหาไฟล์แนบและผลค้นเว็บถูกแปลงเป็น "ข้อความ" แล้วเสียบเป็น system message ก่อน history (กลไก context_blocks เดียวกัน)
  • Chat Completions เป็น stateless — เซิร์ฟเวอร์ต้องส่ง history ทั้งก้อนไป ทุกครั้ง ประวัติเก็บฝั่งเราแยกตาม cookie session_id
  • ทุกบริการภายนอกออกแบบให้ "ไม่ล้ม" — Redis ล่ม / Tavily timeout / vision error ล้วนถูก log แล้วทำงานต่อแบบ degraded ไม่โยน 500

02แผนผังระบบ

เบราว์เซอร์คุย same-origin กับ FastAPI ตัวเดียว ซึ่งเป็นตัวเรียกบริการภายนอกทั้งหมด (ไม่มี API key รั่วไปฝั่งหน้าเว็บ)

โค้ดของเรา บริการภายนอก (REST / OpenAI-compatible)

03เส้นทางของข้อความหนึ่งครั้ง

POST /api/v1/chat/stream — เส้นทางหลักที่หน้าเว็บใช้ ตอบกลับเป็น Server-Sent Events

  1. resolve session — อ่าน cookie session_id (ไม่มีก็สร้างใหม่ + set-cookie 7 วัน)
  2. โหลด context — ดึง history + ไฟล์แนบของบทสนทนาที่ active จาก store
  3. เช็คว่าจะค้นเว็บไหม — _search_should_try() (regex ล้วน ไม่เรียก API)
  4. เปิดสตรีม — ถ้าจะค้น: ส่ง event {"search":""} ทันที (หน้าเว็บโชว์ "กำลังตรวจสอบข้อมูล…")
  5. วางแผนคำค้น + ยิง Tavily — _search_run(): fast-path หรือเรียก classifier แล้ว search.run(); สำเร็จ → {"search": q} + {"sources":[…]}
  6. เรียก LLM แบบสตรีม — llm_client.chat_stream(history, message, context_blocks + ผลค้น)
  7. ส่ง delta ทีละชิ้น — {"delta": "…"} ต่อเนื่อง; error กลางทาง → {"error":true,"message":…}
  8. ปิด — {"done":true} (Typhoon ไม่ส่ง [DONE] เอง จึง yield ตอน loop จบ)
  9. บันทึกประวัติ — เฉพาะเมื่อสตรีมจบสมบูรณ์; กด "หยุด" กลางคัน = ไม่เก็บคำตอบครึ่งๆ

POST /api/v1/chat ทำเหมือนกันแต่ไม่สตรีม (รอจนจบแล้วคืน {"reply": …}) — ใช้เป็น fallback / โดยเทสต์ ไม่แสดงชิปแหล่งอ้างอิง

04โมดูลฝั่งเซิร์ฟเวอร์

แต่ละไฟล์ทำหน้าที่เดียว คุยกันผ่าน type ง่ายๆ (list[dict], str)

main.py

สร้าง FastAPI app, inject truststore (แก้ TLS ในเครือข่ายองค์กร), ตั้ง logging กลาง, mount /static, เสิร์ฟ / (Jinja), /health, include chat_router. CORS เปิดเฉพาะเมื่อตั้ง ALLOWED_ORIGINS

config.py

pydantic-settings อ่านจาก .env ตัวเดียว รวมทุกค่า + property คำนวณ: vision_enabled, search_enabled, redis_rest_url/token (รับได้ทั้งชื่อ KV_REST_API_* และ UPSTASH_REDIS_REST_*)

routers/chat.py

endpoint ทั้งหมดใต้ /api/v1 — แชต, สตรีม, reset, ไฟล์แนบ, บทสนทนา (History), /config, /models. จัดการ cookie, clamp ค่า Settings จาก client, ประกอบ context_blocks, และร้อยเส้นทางค้นเว็บเข้ากับสตรีม

services/llm_client.py

คุย /chat/completions + /models แบบ OpenAI-compatible

  • _build_payload() — ประกอบ messages: system prompt → context_blocks → history → ข้อความใหม่
  • retry อัตโนมัติเมื่อ 429 / 5xx (exponential backoff, เคารพ Retry-After) — สตรีม retry เฉพาะก่อน delta แรก
  • แปลง error เป็นข้อความไทยสุภาพ ไม่หลุด stack trace
  • list_models() รองรับทั้ง {"data":[…]} และ list เปล่า (Typhoon), fallback เป็น LLM_MODEL
services/conversation_store.py

ABC ConversationStore + InMemory… / Redis… (Upstash REST API). get_store() เลือก backend จาก env ครั้งเดียว — มี KV = เก็บถาวร, ไม่มี = ในหน่วยความจำ process. เมธอด get/set_history, *_attachments, reset ทำงานบนบทที่ active; list/new/activate/delete_conversation สำหรับ History

services/documents.py

แปลงไฟล์แนบเป็นข้อความ — ไม่มี AI ถ้าไม่จำเป็น

  • PDF มีข้อความจริง → pymupdf ดึงตรงๆ · หน้าสแกน → render เป็น PNG → typhoon-ocr (ขนานกัน 2)
  • รูปภาพ → OCR + (ถ้าตั้ง VISION_*) Gemini บรรยายภาพ
  • ตัดที่ ATTACHMENT_CONTEXT_CHAR_LIMIT (80k), PDF สูงสุด 12 หน้า, ไฟล์ ≤ 8 MB
services/search.py

ค้นเว็บอัตโนมัติด้วย Tavily — maybe_needs_search(), plan_query(), run(), as_context_block(), sources_payload() (รายละเอียดในหัวข้อ 06)

templates/index.html · static/

หน้าเดียว 2 ฉาก (#landing / #chat-screen) สลับด้วยทรานสิชัน 3D "พุ่งผ่านพอร์ทัล". chat.js (vanilla, ไม่มี framework) อ่าน SSE ด้วย response.body.getReader(), markdown ผ่าน marked + DOMPurify. โลจิกทรานสิชัน / Settings popover / KV-dot อยู่ใน inline <script> ของ template

static/js/voice.js

โหมดสนทนาด้วยเสียง — overlay เต็มจอ (#voice-overlay) + โครงข่ายเซลล์ประสาทบน <canvas>. STT ในเบราว์เซอร์, เรียก /chat/stream เดิม, TTS เป็นเสียงเบราว์เซอร์หรือเซิร์ฟเวอร์เสียงโคลนภายนอกที่ผู้ใช้ตั้ง URL เอง (รายละเอียดหัวข้อ 07). ไม่แตะ backend ของโปรเจกต์นี้

05โครงข้อมูลประวัติ

1 ก้อนต่อ session เก็บที่คีย์ sess:{session_id} (TTL 7 วัน) — เก็บทุกบทสนทนารวมกัน

# GET sess:<session_id>  →  JSON:
{
  "active": "a1b2c3d4e5f6",           # cid ที่กำลังเปิด
  "order":  ["a1b2…", "9f8e…", …],   # ใหม่สุดอยู่หัว, สูงสุด 15
  "conv": {
    "a1b2c3d4e5f6": {
      "title":       "…",           # 48 ตัวแรกของข้อความผู้ใช้แรก
      "updated":     1735900000,
      "messages":    [{"role", "content"}, …],
      "attachments": [{"name", "kind", "text", "meta"}, …]
    }
  }
}

_trim() ตัดบทเก่าสุดทิ้งเมื่อเกิน 15 บท หรือเมื่อ blob รวมเกิน ~900 KB. _ensure() กันข้อมูลเพี้ยน — คืน state ที่มี active/order/conv ครบเสมอ

06ค้นเว็บอัตโนมัติ

แนวทาง "จำแนก → ค้น → เสียบ context" ไม่ใช่ tool-calling loop — เพื่อให้สตรีมคำตอบทำงานปกติทุกกรณี

2 ด่านต้องผ่านทั้งคู่

  1. ด่าน heuristic — maybe_needs_search(): ตัดทักทาย / สั่งเขียน-แปล-สรุป / สมการล้วน / มีไฟล์แนบ ออก แล้วต้องเจอ "สัญญาณ" ข้อมูลสด (_SIGNAL_RE: วันนี้ · ตอนนี้ · ล่าสุด · ราคา · ข่าว · ปี 25xx/20xx · นายก · เปิดตัว · today · price …)
  2. ด่าน classifier — plan_query(): fast-path ถ้าข้อความขึ้นต้นแบบคำค้นชัด (ข่าว… / ราคา… / พยากรณ์อากาศ…) มิฉะนั้นเรียก LLM 1 ครั้งด้วยโปรโตคอล SEARCH: <คำค้น> / SKIP — ค่าตั้งต้นคือ SKIP

แล้วจึง

run() ยิง POST api.tavily.com/search (search_depth: basic, include_answer: false เพื่อความเร็ว) → as_context_block() จัดผลเป็น [1] ชื่อ / url / snippet พร้อมคำสั่งให้โมเดลอ้างอิง [n] → เสียบเป็น context block เพิ่มจากไฟล์แนบ

SSE ที่เพิ่มมาสำหรับหน้าเว็บ: {"search": q} (โชว์แถบสถานะในบับเบิล), {"sources": […]} (ชิปใต้คำตอบ), {"search_done": true} (เคลียร์สถานะเมื่อ classifier ตัดสินไม่ค้น)

ปิดทั้งฟีเจอร์ได้ 2 ทาง: ไม่ตั้ง SEARCH_API_KEY (ปิดถาวร) หรือสวิตช์ในหน้า Settings (ต่อผู้ใช้, localStorage["ts.search"])

07โหมดสนทนาด้วยเสียง

ปุ่ม 🎙️ ในแถบพิมพ์ → overlay เต็มจอ · ช่อง "เสียงพูด" เดียวเลือกได้ทั้งเสียงโคลน Cartesia (ใช้เครดิต, ผ่าน backend) หรือเสียง speechSynthesis ของเบราว์เซอร์ (ฟรี, fallback อัตโนมัติเมื่อ Cartesia ล้มเหลว/ไม่ได้ตั้งค่า)

ชิ้นส่วนใช้อะไร
เสียง → ข้อความWeb Speech API (SpeechRecognition, th-TH) — Chrome / Edge / Chrome-Android เท่านั้น (เบราว์เซอร์อื่นขึ้นข้อความว่าไม่รองรับ)
สมอง/api/v1/chat/stream เดิม — ประวัติ / ค้นเว็บ / ค่า Settings ใช้ต่อได้หมด
ข้อความ → เสียงเลือกจากช่องเดียว <select id="opt-voice"> (localStorage["ts.voice"]) — optgroup "เสียงโคลน (Cartesia)" มาจาก `CARTESIA_VOICES` ที่ต้น voice.js (ค่า option = cartesia:<voice id>) ต่อด้วยเสียง speechSynthesis ของเบราว์เซอร์ (เสียงไทยขึ้นก่อน — รายชื่อมาจาก OS)
สตรีมทีละท่อน เหมือนกันทั้งสองทาง: ตัดคำตอบเป็นท่อน (ท่อนแรกตัดไวสุด ~40 ตัวอักษร, ถัดไปตัดท้ายประโยคหรือทุก 160 ตัวอักษร) ยิงคำขอ TTS ทันทีที่ตัดท่อนได้ระหว่าง LLM ยังพิมพ์อยู่ (prefetch ล่วงหน้าได้สูงสุด 2 ท่อน) แล้วต่อคิวเล่นแบบไม่มีช่องว่างเวลา (gapless) บน AudioContext เดียว พร้อม fade 10ms ที่รอยต่อระหว่างประโยค (scheduleBuffer() — กันเสียง "ตึ๊ด" คลิกตรงขอบที่มาจากคนละ synthesis call)
เลือกเสียงโคลน → สตรีม PCM 24kHz จาก POST /api/v1/tts/stream (backend proxy คีย์ Cartesia ไว้ฝั่งเซิร์ฟเวอร์ ดู routers/tts.py); ท่อนไหนล้มเหลว → fallback speechSynthesis ทันที (ท่อนที่เหลือของคำตอบนี้ใช้เบราว์เซอร์ต่อ กันสลับเสียงไปมา)
ภาพโครงข่ายเซลล์ประสาทบน <canvas> — ขยับตามระดับเสียงจริงจากไมค์ (AnalyserNode) ตอนฟัง; ตอนพูดด้วยเสียงโคลนป้อน RMS จาก AnalyserNode ที่ต่อรวมทุกท่อนในคิวเดียว ทำให้พัลส์ตรงกับคำพูดจริงตลอดทั้งคำตอบ (เสียงเบราว์เซอร์ยังใช้พัลส์จาก onboundary), นิ่งเมื่อ prefers-reduced-motion

ลูปสนทนา (state machine ใน voice.js)

  1. listening — SpeechRecognition เก็บเสียง; ผลชั่วคราวโชว์เป็นคำบรรยาย
  2. thinking — เมื่อได้ผลสุดท้าย → POST /chat/stream (พร้อม chatOptions() + voice: true) อ่าน SSE; ทุกครั้งที่ตัดท่อนคำตอบได้ → enqueueSpeech() ทันที ไม่รอสตรีมจบ
  3. speaking — pumpSpeakQueue() ดึงท่อนถัดไปมาพูดทีละท่อน (เสียงโคลน: speakCartesiaChunk() → scheduleBuffer() ต่อคิว gapless / เสียงเบราว์เซอร์: speakBrowserChunk()) จนกว่าคิวจะว่างและสตรีมจบ
  4. → listening — ท่อนสุดท้ายเล่นจบ (source.onended / utterance.onend) แล้วไม่มีท่อนค้าง → เริ่มฟังใหม่อัตโนมัติ

แตะที่วงกลม = พูดแทรก (speakSession++ ทำให้งาน async ของคิวเก่าทั้งหมดเห็นว่าถูกยกเลิก แล้ว stopAllTts() หยุดทุก source ที่กำลังเล่น/รอเล่น + abort คำขอ /tts ที่ค้างอยู่ แล้วกลับไปฟัง) · ปุ่ม ✕ หรือ Esc = ปิด overlay แล้วเรียก window.voiceSyncChat (เพิ่มใน chat.js) เพื่อรีเฟรชแชต + รายการบทสนทนา

ต้องเป็น HTTPS (Vercel เป็นอยู่แล้ว) ไมโครโฟนถึงจะใช้ได้ · คำบรรยายสลับเปิด/ปิดได้ (localStorage["ts.captions"])

08Endpoint

ทั้งหมดขึ้นต้น /api/v1 · ผูก session ด้วย cookie session_id

Method + pathทำอะไร
POST /chat/streamแชตแบบสตรีม (SSE) — เส้นทางหลัก
POST /chatแชตแบบไม่สตรีม คืน {"reply"}
POST /chat/resetล้างเนื้อหาบทที่ active (ไม่ออก session ใหม่)
GET /historyข้อความของบทที่ active (โหลดตอนเปิดหน้า)
GET /conversationsรายการบทสนทนาทั้งหมด (id, title, updated, count, active)
POST /conversationsเริ่มบทใหม่ ("แชตใหม่")
POST /conversations/{cid}/activateสลับไปบทนั้น คืน messages + attachments
DELETE /conversations/{cid}ลบบทสนทนา
GET/POST /attachments, DELETE /attachments/{i}รายการ / อัปโหลด / ลบไฟล์แนบของบทที่ active
GET /configค่าตั้งต้นหน้า Settings: temperature, max_tokens, model, kv, web_search
GET /tts/configโหมดเสียง — {"enabled"} บอกว่าตั้งค่า Cartesia ไว้ไหม (ไม่หลุด API key)
POST /tts/streamโหมดเสียง — proxy ไป Cartesia เก็บ API key ไว้ฝั่งเซิร์ฟเวอร์เท่านั้น รับ {"text","voice_id"?} สตรีม PCM 24kHz mono กลับ (ดู routers/tts.py) — ไม่ผูก session_id
GET /modelsproxy รายชื่อโมเดล (ไม่หลุด API key)
GET /healthเช็คว่าเซิร์ฟเวอร์ยังรัน (นอก /api/v1)

09Deploy

Vercel Python serverless · repo github.com/Myname30275/chatbot-typhoon (private)

  • api/index.py = entrypoint เดียว — เพิ่ม project root เข้า sys.path แล้ว from main import app
  • vercel.json ต้องเป็นฟอร์แมต builds / routes — ฟอร์แมตใหม่ (functions / rewrites) จะ rewrite ทุก path ไป /api/index ทำให้ FastAPI routing พังทั้งหน้า (เจอ 404/ขาว)
  • maxDuration ตั้งใน Dashboard (Settings → Functions → 60s) ไม่ใช่ใน vercel.json — จำเป็นเพราะ OCR หลายหน้า และรอบที่ค้นเว็บใช้เวลาเกิน default 10s
  • แก้ env ต้อง Redeploy ถึงจะมีผล
  • สาขา feat/landing-ui อยู่ใน Vercel Preview — ยังไม่ merge เข้า main / production
