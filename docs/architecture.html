01โจทย์ของร้าน

แชทบอทตอบลูกค้าแทนเจ้าของร้าน ภายใต้เงื่อนไข 3 ข้อ ทุกส่วนของระบบออกแบบมาเพื่อรักษาเงื่อนไขเหล่านี้

ตอบจากข้อมูลจริง

ราคา เวลา นโยบาย มาจาก shop/catalog.json ไฟล์เดียว ห้ามแต่งข้อมูลเอง

ใช้เองได้ไม่ต้องสอน

ปุ่มคำถามด่วน ส่งรูปแล้วได้ราคาทันที มีสถานะบอกทุกขั้น

ไม่ถูกหลอก

ส่วนลดปลอม ข้อมูลลูกค้าคนอื่น บริการที่ไม่มี — กันด้วยกฎในโค้ด ไม่ใช่แค่ prompt

05Guardrails 3 ด่าน (ไม่ต้องใช้ key เพิ่ม)

ด่านตรวจอะไรถ้าไม่ผ่าน
1 กฎ (input_rules.py)≤ 1000 ตัวอักษร, ≤ 15 ข้อความ/นาที/session, blocklist.txt (แก้แล้วมีผลทันที), รูปแบบ prompt injection — ไม่เรียก APIตอบปฏิเสธภาษาไทยตามหมวด ไม่บันทึกประวัติ
2 judge (judge.py)Typhoon จำแนก SAFE / INJECTION / PRIVACY / HARMFUL ตาม prompts/guard_judge.txt — รันพร้อม RAGปฏิเสธโดยไม่เรียก LLM ตอบ · ตัวตรวจล่ม = ปล่อยผ่าน (ตั้ง GUARD_JUDGE_FAIL_CLOSED=true เพื่อปฏิเสธแทน)
3 ขาออก (output_guard.py)ทีละประโยค: ยอดบาทต้องมีใน catalog (หรือผลรวม 1–3 รายการ, หรือหลังลด 10%), % ต้องมีจริง, ห้ามเบอร์/อีเมล/เลขบัตรที่ลูกค้าไม่ได้ให้เอง, ห้ามหลุดกฎภายในแทนคำตอบด้วย fallback ของร้าน

ความเสี่ยงตามโจทย์ร้าน

ลูกค้าพยายามสิ่งที่กันไว้
ขอส่วนลดที่ไม่มีราคามาจาก catalog เท่านั้น · prompt ต้องทำข้อ 8 · ด่าน 3 บล็อกตัวเลขที่ไม่มีจริง
ขอข้อมูลลูกค้าคนอื่นประวัติแยกตาม session บอทเข้าถึงข้อมูลคนอื่นไม่ได้เลย · ด่าน 2 PRIVACY
ขอบริการที่ร้านไม่มีรายการ not_offered · prompt ให้ปฏิเสธพร้อมยกตัวอย่างชัดเจน
ถามอาการป่วย / ยาแนะนำพบสัตวแพทย์ ห้ามวินิจฉัย
“ลืมคำสั่งเดิม”, อ้างเป็นผู้จัดการด่าน 1 regex + ด่าน 2 INJECTION · ด่าน 3 ตรวจการหลุดกฎภายใน
ส่งสลิปปลอมบอทไม่ยืนยันการชำระเงินเอง แอดมินเป็นผู้ยืนยัน
ใช้สลิปใบเดิมจองหลายคิวเลขอ้างอิงสลิปเก็บด้วย SET NX — ใบเดิมใช้ซ้ำไม่ได้
จองชนกันในช่องเดียวตัวนับ INCR แบบ atomic เกิน 2 คิวได้ 409
ดูใบจองของคนอื่นผูกกับ session คนอื่นได้ 404 · เบอร์บนใบจองปิดกลาง
เดารหัสหลังบ้าน5 ครั้ง/นาที/IP · cookie ลงลายเซ็น HMAC · SameSite=Strict
ราคาหน้าร้านไม่ตรงกับที่แจ้งใบจองไม่มีราคา · นโยบายชั่งน้ำหนักหน้าร้านอยู่ในคลังความรู้

06RAG ข้อมูลร้าน

  • คลังความรู้: shop/catalog.json (บริการ 8, บริการเสริม 4, รับ-ส่ง 2, แพ็กเกจ, สินค้า 3), policies.md, faq.md (10 ข้อ) → แบ่งตามความหมายได้ 29 ชิ้น (บริการละชิ้น ราคาทุกไซส์จึงไม่ถูกหั่นกลางตาราง)
  • index: python -m rag.build_index สร้าง embedding ล่วงหน้า (Gemini gemini-embedding-001, 768 มิติ) เก็บใน rag/index.json — ไม่ต้องมี vector DB
  • การค้น: 0.7 × cosine ของ embedding + 0.3 × TF-IDF character n-gram (2–3 ตัวอักษร ไม่ต้องตัดคำไทย) · คำค้น = คำถามก่อนหน้า 1 ข้อความ + คำถามใหม่ · เอา 4 ชิ้นบนสุด
  • กันข้อมูลเก่า: index เก็บ hash ของข้อมูลร้าน ถ้าแก้ shop/ แล้วลืม build ใหม่ ระบบจะไม่ใช้ index เก่า แต่ค้นแบบ TF-IDF จากข้อมูลล่าสุดแทน (Gemini ล่มก็ใช้ทางนี้)
  • ผลทดสอบ: hit@4 = 16/16 คำถาม (docs/test-log.md)

07หน้าเว็บและอวตาร

หน้า /

หัวเรื่อง + ภาพหมา 3 ตัว, ปุ่ม “ส่งรูปน้องให้ประเมินราคา”, ป้ายราคาตามไซส์ (render จาก catalog.json), วิธีจอง 3 ขั้น, บริการที่ร้านไม่มี, ติดต่อร้าน

หน้าต่างแชท

ปุ่มลอยมุมขวาล่าง → แผงเลื่อนออกจากขวา (มือถือเต็มจอ) · ทักทาย + คำถามด่วน 5 ปุ่ม · ส่งรูปเห็นภาพย่อ · ชิป “ข้อมูลจากร้าน”

ป๊อปอัปจองคิว + ใบจอง

3 ขั้น: ชื่อน้อง/เจ้าของ/เบอร์ → เลือกช่องเวลาที่ว่าง → แนบสลิป · ได้ใบจองในแชท (ไม่มีราคา/สลิป/สถานะ) บันทึกเป็นรูปได้ · เช็คสถานะที่หน้า /check ด้วยเบอร์โทร

หน้า /admin

หลังบ้านเจ้าของร้าน: ตารางคิวรายสัปดาห์ ปฏิทินรายเดือน ค้นเลขจอง ดูรูปน้อง/สลิป กดยืนยัน มาแล้ว หรือยกเลิก

หน้า /avatar

พนักงาน VRM ยืนหลังเคาน์เตอร์ตั้งแต่เปิดหน้า · ท่า Idle · ปากขยับตามเสียงจริง · คำบรรยาย · เลือกเสียง Cartesia ได้ 6 เสียง

สถานะที่ UI บอกลูกค้า

แชท: พร้อมตอบ · กำลังพิมพ์… (หัวน้องหอมเอียง) · กำลังดูรูปน้อง… (หัวผงก) · คำตอบถูกปฏิเสธ (บับเบิลเส้นประ) · error พร้อมปุ่ม “ส่งอีกครั้ง” · ปุ่มหยุดระหว่างตอบ
อวตาร: กำลังโหลด · กำลังฟัง (ขอบเวทีฟ้า) · กำลังคิด · กำลังพูด · โหลดตัวละครไม่สำเร็จ · เบราว์เซอร์ไม่มีเสียงไทย

ลูปคุยด้วยเสียง (voice.js)

08จองคิวและหลังบ้าน

จองผ่านป๊อปอัปในแชท ไม่ให้บอทเก็บข้อมูลจากบทสนทนา ทุกขั้นเป็นโค้ด (ไม่ผ่าน LLM) และถ้าขั้นไหนไม่ผ่าน ช่องเวลาที่กันไว้จะถูกคืนทันที ลูกค้าแก้แล้วส่งใหม่ได้โดยข้อมูลที่กรอกไม่หาย

หลังบ้าน /admin

  • เข้าสู่ระบบ: รหัสจาก ADMIN_PASSWORD · cookie หมดอายุ.HMAC (ปลอมไม่ได้, SameSite=Strict, 12 ชม.) · ผิดเกิน 5 ครั้ง/นาที/IP ต้องรอ · ไม่ตั้งรหัส = ปิดหลังบ้าน
  • มุมมอง: ตารางรายสัปดาห์ (วัน × ช่องเวลา, สีตามสถานะ, ⚠ ต้องตรวจสลิปเอง) · ปฏิทินรายเดือน (จำนวนคิว + รอยืนยัน) · ค้นเลขจอง (ลูกค้ายื่นใบจองที่หน้าร้าน) · รีเฟรชเองทุก 60 วินาที
  • สถานะ: รอร้านยืนยัน → ยืนยันแล้ว → มาใช้บริการแล้ว · หรือ ยกเลิก (คืนช่องเวลาทันที) · เปลี่ยนผิดลำดับไม่ได้
  • ที่เก็บ: Redis / Vercel KV ตัวเดียวกับประวัติแชท — ตัวนับช่อง INCR, เลขสลิป SET NX, ดัชนีเวลา sorted set · Redis ล่ม = ตอบ 503 ไม่ทำเหมือนจองสำเร็จ

12เหตุผลการออกแบบ (ใช้ตอบ Q&A)

ทำไมราคาต้องมาจากโค้ด ไม่ให้ LLM คิด
LLM ถูกหลอกได้เสมอ (OWASP LLM01) กฎสำคัญจึงอยู่ในโค้ด ต่อให้หลอกบอทสำเร็จ บอทก็ไม่มีสิทธิ์สร้างราคาใหม่ — ด่าน 3 ตัดทิ้ง
ทำไมมีแกนกลาง assistant.py
หน้าแชทและโหมดเสียงต้องได้กฎชุดเดียวกัน ถ้าเขียนแยกแต่ละช่องทางจะมีช่องโหว่ในช่องทางที่ลืมใส่กฎ
ทำไม RAG เขียนเอง ไม่ใช้ LightRAG
คลังความรู้เล็ก (29 ชิ้น) และ Vercel serverless รัน Docker ไม่ได้ จึงสร้าง embedding ล่วงหน้าเป็นไฟล์แล้วค้นในหน่วยความจำ
ทำไม hybrid (embedding + TF-IDF)
embedding จับความหมาย (“หมาตัวใหญ่” ≈ “สุนัขใหญ่”) ส่วน TF-IDF จับคำเฉพาะ (“ต่อมกลิ่น”) และเป็นทางสำรองเมื่อ Gemini ล่ม
ทำไมคำตอบแรกหลังส่งรูปสร้างด้วยโค้ด
ทดสอบจริงแล้ว Typhoon เล่าผลวิเคราะห์ไม่สม่ำเสมอ (บางรอบตอบว่ารับอาบน้ำจระเข้) — แนวเดียวกับ Workshop Week 10
ทำไม judge ใช้ Typhoon แทน Llama Guard
ใช้ key เดิม ไม่มีค่าใช้จ่ายเพิ่ม และเข้าใจภาษาไทยในบริบทร้าน (“หมาดุ กัดคน รับไหม” = SAFE)
ทำไมจองด้วยฟอร์ม ไม่ให้บอทเก็บข้อมูลจากแชท
LLM ดึงชื่อ/เบอร์/วันเวลาจากบทสนทนาพลาดได้และตรวจสอบยาก ฟอร์ม 3 ช่อง + ปุ่มเลือกช่องได้ข้อมูลแน่นอน และกันจองซ้อนได้จริง
ทำไมใบจองไม่มีราคา
ราคาในแชทเป็นราคาประเมิน ร้านชั่งน้ำหนักจริงหน้าร้านเสมอ ถ้าใบจองมีราคาแล้วไม่ตรง (หรือ Vision เดาน้ำหนักผิด) จะเป็นข้อโต้แย้ง
ทำไมทำใบจองเป็นรูปในเบราว์เซอร์
Pillow/WeasyPrint วางสระ-วรรณยุกต์ไทยผิดถ้าไม่มี libraqm และ Vercel ไม่มี library ระบบที่ต้องใช้ เบราว์เซอร์แสดงภาษาไทยถูกเสมอ
ทำไมปิดค้นเว็บ
โจทย์ห้ามแต่งข้อมูล ข้อมูลจากเว็บอาจขัดกับราคาและนโยบายจริงของร้าน
รองรับลูกค้า 10 เท่าได้อย่างไร
serverless ขยาย instance เอง state ทั้งหมดอยู่ใน Redis · RAG ไม่มี DB · จุดคอขวดคือโควตา Typhoon/Gemini — แก้ด้วย cache คำถามซ้ำ และ rate limit ด่าน 1 ที่ย้ายไปนับใน Redis
