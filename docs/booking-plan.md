## 1. ข้อตกลงที่ใช้ออกแบบ

| เรื่อง | ข้อตกลง | เหตุผล |
|---|---|---|
| ฟอร์มจอง | กรอกเองแค่ **ชื่อน้อง, ชื่อเจ้าของ, เบอร์โทร** + กดเลือกวัน/ช่องเวลา + แนบสลิป | สั้นที่สุด ข้อมูลที่เหลือร้านดูหน้างาน |
| ราคา | **ไม่มีราคาบนใบจอง** มีหมายเหตุ "ราคาจริงแจ้งหลังชั่งน้ำหนักหน้าร้าน" | ราคาในแชทเป็นราคาประเมิน ร้านชั่งใหม่หน้าร้านเสมอ ถ้าใบจองมีราคาแล้วไม่ตรงหน้าร้าน (หรือ Vision เดาน้ำหนักผิด) จะเป็นข้อโต้แย้ง |

| การยืนยัน | ส่งสลิปผ่าน → ใบจองสถานะ **"รอร้านยืนยัน"** · เจ้าของร้านกดยืนยันใน `/admin` → **"ยืนยันแล้ว"** | กฎเดิม: บอทไม่ยืนยันการชำระเงินเอง (สลิปปลอมได้) |
| ข้อมูลที่ต้องมาจากโค้ด | ช่องเวลาว่าง, เลขจอง, ผลตรวจสลิป, สถานะ | ไม่ให้ LLM สร้างหรือแก้ข้อมูลการจอง |

## 2. เส้นทางของลูกค้า

```
แชท: ส่งรูปน้อง → ราคาประเมินตามไซส์ + ปุ่ม [จองคิว]
                                           │
ป๊อปอัป ขั้น 1  ชื่อน้อง · ชื่อเจ้าของ · เบอร์โทร  (รูปน้อง: ใช้รูปที่ส่งในแชท / แนบใหม่)
ป๊อปอัป ขั้น 2  ปฏิทิน 14 วันข้างหน้า → ช่องเวลาที่ว่าง (เต็ม = กดไม่ได้)
ป๊อปอัป ขั้น 3  เลขบัญชีร้าน + มัดจำ 50 บาท → แนบสลิป → [ยืนยันการจอง]
                                           │
เซิร์ฟเวอร์: ตรวจฟอร์ม → จองช่องเวลาแบบ atomic → Gemini อ่านสลิป → ตรวจยอด/ชื่อบัญชี/เลขอ้างอิงซ้ำ
                                           │
แชท: การ์ดใบจอง (สถานะ รอร้านยืนยัน) + ปุ่ม [บันทึกเป็นรูป]
เจ้าของร้าน /admin: เห็นคิวในตารางสัปดาห์ → เปิดดูรูปน้อง/สลิป → [ยืนยัน] → ใบจองของลูกค้าเปลี่ยนเป็น "ยืนยันแล้ว"
```

ทางเข้าป๊อปอัป 3 ทาง
1. ปุ่ม **จองคิว** ใต้คำตอบประเมินราคาจากรูป (ทางหลัก)
2. ปุ่มคำถามด่วน **จองคิว** ในข้อความต้อนรับ (แทน "จองคิวยังไง")
3. ลูกค้าพิมพ์ข้อความที่มีคำว่า จอง / นัด / คิว → ต่อปุ่มไว้ใต้คำตอบของบอท (ตรวจด้วย regex ในหน้าเว็บ ไม่ใช้ LLM)
4. โหมดเสียง (`/avatar`): ลูกค้าพูดเรื่องจอง/นัด/คิว หรือบอทบอกให้กดจองคิว → การ์ดปุ่ม "จองคิว" เด้งขึ้นข้างอวตาร
   กดแล้วไป `/?book=1` → หน้าแรกเปิดแชท (มีบทสนทนาเสียงอยู่แล้ว เพราะ session เดียวกัน) + ป๊อปอัปจองทันที

## 3. ใบจอง (ไม่มีราคา)

```
┌────────────────────────────────────┐
│ [โลโก้] Hom Hom Grooming   ใบจองคิว   │
│ [ รูปน้อง ]  ถั่วแดง                   │
│              วันเวลานัด ส. 4 ต.ค. 10:00 น. │
│ น้อง      ถั่วแดง                     │
│ เจ้าของ    คุณสมใจ   โทร 081-xxx-5678  │
│ วันเวลา    ส. 4 ต.ค. 2569  10:00 น.    │
│ เลขจอง    HH-1004-03                 │
│ ราคาจริงแจ้งหลังชั่งน้ำหนักหน้าร้าน       │
└────────────────────────────────────┘
```

- สร้างเป็น **การ์ด HTML ในหน้าเว็บ** แล้วแปลงเป็น PNG ในเบราว์เซอร์ (`html-to-image` จาก jsDelivr)
  — ไม่ทำ PDF/รูปฝั่งเซิร์ฟเวอร์ เพราะ Pillow/WeasyPrint วางสระ-วรรณยุกต์ไทยผิดถ้าไม่มี libraqm และ Vercel ไม่มี library ระบบที่ต้องใช้
- (ปรับ 2 ต.ค.) **ไม่มีสลิป ไม่มี QR และไม่มีสถานะบนใบจอง** — สลิปดูได้เฉพาะหลังบ้าน · QR สแกนแล้วได้แค่ข้อความ ไม่ช่วยตรวจอะไร ·
  สถานะย้ายไปหน้า **เช็คคิว `/check`** (กรอกเบอร์ที่ใช้จอง) เพราะรูปใบจองที่ลูกค้าบันทึกไปแล้วอัปเดตสถานะไม่ได้
- หน้าเช็คคิวค้นด้วยเบอร์อย่างเดียว จึงแสดงแค่ชื่อน้อง วันเวลา เลขจอง สถานะ (ไม่มีชื่อเจ้าของ/รูป/สลิป) และจำกัด 10 ครั้ง/นาที กันไล่เดาเบอร์
- เบอร์โทรบนใบจองปิดกลาง (`081-xxx-5678`) เผื่อลูกค้าเอารูปไปแชร์ · ในหลังบ้านเห็นเต็ม
- เปิดดูใบจองเดิมได้อีกจากปุ่ม **ใบจองของฉัน** ในเมนูแชท (ดึงตาม session)

## 4. ช่องเวลา (ตั้งค่าใน `shop/catalog.json`)

```json
"booking": {
  "open": "09:00",
  "last_start": "16:00",
  "slot_minutes": 60,
  "capacity_per_slot": 2,
  "closed_weekdays": [0],
  "min_days_ahead": 1,
  "max_days_ahead": 14
}
```

- ตรงกับนโยบายเดิม: เปิด อ.–อา. 09:00–18:00, รับคิวสุดท้าย 16:00, จองล่วงหน้าอย่างน้อย 1 วัน
- `capacity_per_slot` = จำนวนช่างที่รับพร้อมกัน (ค่าเริ่ม 2 — ปรับได้)
- ไม่ถามบริการในฟอร์ม → 1 การจอง = 1 ช่อง (ร้านจัดเวลาจริงหน้างาน)
- เวลาทั้งหมดคิดเป็นเวลาไทยด้วย `timezone(timedelta(hours=7))` (Vercel รันเป็น UTC และ `zoneinfo` บน Windows ต้องลง `tzdata` เพิ่ม)

## 5. โครงข้อมูล (Redis / Vercel KV — ตัวเดียวกับประวัติแชท)

| key | ค่า | หมายเหตุ |
|---|---|---|
| `booking:<id>` | JSON: `id, session_id, pet_name, owner_name, phone, slot_start, status, slip{amount, receiver_ok, reference, auto_ok}, created_at, updated_at` | ไม่มีราคา · TTL 180 วัน |
| `booking_img:<id>:pet`, `booking_img:<id>:slip` | JPEG (base64) ย่อฝั่งเบราว์เซอร์ ≤ 800 px (~80 KB) | ไม่ต้องเพิ่ม Pillow · ขนาดไม่เกินเพดาน request ของ Upstash |
| `bookings:by_time` | sorted set: score = เวลานัด (epoch), member = id | ดึงรายสัปดาห์/รายเดือนด้วย `ZRANGEBYSCORE` |
| `slotcount:<YYYY-MM-DDTHH:MM>` | ตัวนับ | `INCR` แบบ atomic → เกิน capacity ให้ `DECR` คืนแล้วตอบ 409 · ยกเลิกคิว = `DECR` |
| `slipref:<reference>` | id ของการจอง | `SET NX` — สลิปใบเดิมใช้จองซ้ำไม่ได้ |
| `bookings:session:<sid>` | list ของ id | "ใบจองของฉัน" |
| `seq:<YYYYMMDD>` | ตัวนับ | เลขจอง `HH-MMDD-NN` |

โค้ดแยกเป็น `BookingStore` แบบ in-memory (รันในเครื่อง/เทส) กับ Redis (Vercel) เหมือน `conversation_store.py`

**สถานะ:** `pending` (รอร้านยืนยัน) → `confirmed` (ยืนยันแล้ว) → `done` (มาแล้ว) · หรือ `cancelled`
ถ้า Gemini อ่านสลิปไม่ได้ (ล่ม/ภาพไม่ชัด) ยังรับจองได้ แต่ `slip.auto_ok = false` → หลังบ้านขึ้นป้าย "ต้องตรวจสลิปเอง"

## 6. การตรวจสลิปตอนจอง

ใช้ `vision/image_analyzer.analyze()` ตัวเดิม แล้วเช็กด้วยโค้ด

| เจอ | ผล |
|---|---|
| ไม่ใช่รูปสลิป | ไม่รับ · "รูปนี้ไม่ใช่สลิปโอนเงิน" |
| ยอดไม่ใช่ 50 บาท | ไม่รับ · บอกยอดที่อ่านได้ |
| ชื่อผู้รับไม่ใช่บัญชีร้าน | ไม่รับ · ให้ตรวจบัญชี |
| เลขอ้างอิงเคยใช้แล้ว | ไม่รับ · "สลิปนี้ถูกใช้จองไปแล้ว" |
| อ่านไม่ได้ / Gemini ล่ม | รับ (`auto_ok=false`) → เจ้าของร้านตรวจเอง |

ถ้าไม่รับ ช่องเวลาที่กันไว้จะถูกคืนทันที และข้อมูลในฟอร์มยังอยู่ครบให้แนบสลิปใหม่

## 7. API

| Method · Path | หน้าที่ | สิทธิ์ |
|---|---|---|
| `GET /api/v1/booking/slots` | ช่องเวลา 14 วันข้างหน้า + ว่าง/เต็ม | ทุกคน |
| `POST /api/v1/booking` | multipart: `pet_name, owner_name, phone, slot, pet_photo, slip` → ใบจอง | session (cookie เดิม) · ผ่าน rate limit ด่าน 1 |
| `GET /api/v1/booking/mine` | ใบจองของ session นี้ | เจ้าของ session |
| `GET /api/v1/booking/{id}/image/{pet\|slip}` | รูปบนใบจอง | เจ้าของ session หรือแอดมิน · คนอื่นได้ 404 |
| `GET /admin` | หน้าหลังบ้าน (ยังไม่ login → ฟอร์มรหัสผ่าน) | — |
| `POST /admin/login`, `POST /admin/logout` | รหัสจาก `ADMIN_PASSWORD` → cookie ลงลายเซ็น HMAC | — |
| `GET /api/v1/admin/bookings?from=&to=` | รายการคิวช่วงวันที่ | แอดมิน |
| `POST /api/v1/admin/bookings/{id}/status` | `confirmed / done / cancelled` | แอดมิน |

การตรวจฟอร์มฝั่งเซิร์ฟเวอร์: ชื่อ 1–40 ตัวอักษร (ตัดอักขระควบคุม), เบอร์ `0` + 9 หลัก, ช่องเวลาต้องอยู่ในรายการที่เปิดจริง, รูป ≤ 1 MB และเป็น JPEG/PNG/WebP

## 8. หลังบ้าน `/admin`

- **รายสัปดาห์ (ค่าเริ่มต้น):** คอลัมน์ อ.–อา. × แถว 09:00–16:00 · ในช่องเป็นชิปชื่อน้อง สีตามสถานะ · ปุ่มสัปดาห์ก่อน/ถัดไป

- **กดคิว → แผงรายละเอียด:** รูปน้อง, รูปสลิป, ชื่อ, เบอร์ (กดโทรได้), ผลตรวจสลิป, ปุ่ม ยืนยัน / มาแล้ว / ยกเลิก

- ธีมเดียวกับหน้าร้าน · ต้อง login · ไม่มีลิงก์จากหน้าลูกค้า

## 10. การทดสอบ

- ช่องเวลา: วันจันทร์ปิด, ไม่มีช่องหลัง 16:00, ไม่มีวันนี้/วันที่ผ่านมา, ไม่เกิน 14 วัน
- จองพร้อมกันเกิน capacity → คนที่เกินได้ 409 และตัวนับไม่ติดลบ/ไม่ค้าง
- สลิป: ยอดผิด, ชื่อบัญชีผิด, เลขอ้างอิงซ้ำ, ไม่ใช่สลิป, Gemini ล่ม (รับแบบ `auto_ok=false`) · ไม่รับแล้วช่องเวลาถูกคืน
- ความเป็นส่วนตัว: session อื่นขอใบจอง/รูปของคนอื่น → 404 · API แอดมินไม่มี cookie → 401
- ข้อมูลใบจองที่ส่งให้หน้าเว็บ **ไม่มีฟิลด์ราคา**
- ฟอร์ม: เบอร์ผิดรูปแบบ, ชื่อยาวเกิน, รูปใหญ่เกิน
- e2e ด้วย Playwright: ส่งรูป → จองคิว → ได้การ์ด → แอดมินยืนยัน → การ์ดเปลี่ยนสถานะ

- rate limit นับ 2 ชั้น: ต่อ session (5 ครั้ง/นาที) และต่อ IP (20 ครั้ง/นาที) · ส่ง cookie กลับทุกกรณีรวมตอน error
  (เทสจับได้ว่าถ้าส่งเฉพาะตอนสำเร็จ คนที่จองไม่ผ่านจะได้ session ใหม่ทุกครั้งและหลุด limit)

- (ขั้น 2) ลิงก์ Google Fonts ต้องมี `crossorigin="anonymous"` ไม่งั้น html-to-image อ่าน @font-face ไม่ได้และรูปใบจองใช้ฟอนต์ระบบ
